## Fixed: infinite /dashboard ↔ /login redirect loop (LMS)

**Symptom:** dev log flooded with `GET /dashboard 200` (~one per second, no `/login`
lines because proxy-level 307s are not logged by `next dev`).

**Cause:** two different notions of "signed in".
- `src/proxy.ts` only checks that the session **cookie exists** → redirected `/login`
  → `/dashboard`.
- `requireUser()` in `src/lib/session.ts` checks the **real session** → redirected
  `/dashboard` → `/login`.
With a stale cookie (expired, revoked, or DB re-seeded) the two bounce each other
forever. The 1s cadence comes from Cache Components emitting the redirect as a
`200` + `<meta http-equiv="refresh" content="1;url=/login">` (redirect fired inside
`<Suspense>` after the shell flushed), not a real 307.

**Fix:**
- Removed the `hasSessionCookie && AUTH_PAGES → /dashboard` rule from `src/proxy.ts`
  (comment left in place explaining why it must not come back).
- Added `src/components/redirect-if-signed-in.tsx` — a real `getSessionUser()` check
  that redirects to `homeForRole(user.role)`; wrapped in `<Suspense fallback={null}>`
  on both `src/app/login/page.tsx` and `src/app/register/page.tsx`.

**Verified** (against a real dev server + seeded siswa account): stale cookie →
`/login` renders the form (200, no loop); valid session → `/login` redirects to
`/siswa`; `/dashboard` still routes by role.

**Note:** `/dashboard` and `/login` redirects are client-side (200 + 1s meta
refresh) because of `cacheComponents: true`. Making `/dashboard` a `route.ts`
would give a true 307 if that delay ever matters.

**Env gotcha:** C: was at 100% (51 MB free) mid-session — the shell died with
`0xC0000142` and writes failed with ENOSPC. Use `D:/tmp` for scratch, and remember
`curl` needs `--noproxy '*'` here (an `http_proxy` env var swallows localhost).

### Next 16 "instant navigation" rule — `await params` must sit in Suspense

Dev overlay error `instant-shell-url-data` on `/admin/[section]`: awaiting `params`
in the page body blocks the instant shell. Fix (per
`node_modules/next/dist/docs/01-app/02-guides/instant-navigation.md`): keep the page
sync and move `await params` into a child rendered inside `<Suspense>`:

```tsx
export default function Page({ params }) {
  return <Suspense fallback={<SectionSkeleton />}><SectionContent params={params} /></Suspense>
}
```

`generateMetadata` may still await `params` — metadata is not part of the shell.
Remember this for every dynamic route added later (`[id]`, `[ruang]`, …).

## Halaman Mata Pelajaran (/admin/mapel)

Built on the same skeleton as Kelas: `mapel-shared.ts` (pure) + `mapel.ts`
(pool, `export *`) + `actions/mapel.ts` + `mapel-directory/dialog/row-actions`.

**Ordering is not alphabetical.** `order by case kelompok when 'Umum' then 0
when 'Kejuruan' then 1 when 'Muatan Lokal' then 2 end, nama` — a plain
`order by kelompok` sorts Kejuruan first, which buries the subjects every class
takes. Same CASE is the reason `KELOMPOK_ORDER` exists in `mapel-shared.ts` for
client-side needs.

**"Dipakai" counts rooms across every academic year**, matching the reference
app (`Ruang::selectRaw(...)->groupBy('mapel_id')`). Not filtered to the active
year on purpose: last year's rooms still carry the subject's history.

**Delete rule.** Guard rides inside the DELETE (`and not exists (select 1 from
ruang r where r.mapel_id = m.id)`), so nothing can slip in between check and
delete. Message: "Mapel masih dipakai di ruang belajar." I also flipped the FK
`ruang_mapel_id_fkey` from **on delete cascade to on delete restrict** — the
cascade made the database an accomplice to exactly the delete the product
forbids. Verified: raw `delete from mapel where kode='MTK'` inside a rolled-back
transaction now fails with 23001.

**Bounds.** `mapel_kode_length` (1–15) and `mapel_nama_length` (1–120) added by
`scripts/migrate-mapel.ts` (idempotent, guarded by `pg_constraint` lookups like

## Halaman Jurusan (/admin/jurusan)

Same skeleton again: `jurusan-shared.ts` + `jurusan.ts` + `actions/jurusan.ts` +
`jurusan-directory/dialog/row-actions` + page. Two fields, so the dialog is
shorter than Mapel's — Kode → Nama → Simpan.

**`listJurusan` moved.** It used to live in `kelas.ts` (the class form's
dropdown). It is now `listJurusanOptions()` in `jurusan.ts`, and `kelas.ts`
re-exports it as `listJurusan` so existing callers keep working. One query, one
owner; `jurusan.ts` does not import `kelas.ts`, so no cycle.

**Delete rule.** FK `kelas.jurusan_id` is `on delete set null` — Postgres would
silently orphan classes rather than complain, which is exactly what the
blueprint forbids. The guard therefore rides inside the DELETE
(`and not exists (select 1 from kelas k where k.jurusan_id = j.id)`), message
"Jurusan masih dipakai kelas.". The FK is left as `set null` on purpose: it is
the fallback, the app is the gate.

**Menu gating.** `nav-config.ts` gained `NavItem.onlyForJurusan` and
`adminNavFor(jenjang)`, which drops the item (and any group left empty) for
SD/SMP. `app-sidebar.tsx` now takes a `jenjang` prop, fed by
`AdminShell` (`Promise.all([requireRole("admin"), getJenjang()])`). The route
itself calls `notFound()` for SD/SMP — menu gone and URL gone must agree.

**Terminology.** `istilahJurusan(jenjang)` → "program keahlian" (SMK) /
"peminatan" (SMA). Used in the dialog description and the empty state; the page
subtitle stays jenjang-neutral because the header sits *outside* the Suspense
boundary and cannot read `jenjang`.

console errors — order AKL,BD,TKJ; counts 2/1/3; stats 3/6/2; search by kode and
by name; create with auto-uppercase; duplicate kode; edit prefill + rename;
delete refused for TKJ; own test row deleted; 390px no overflow.
