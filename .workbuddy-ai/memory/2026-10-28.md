### Design decisions worth remembering

- **One endpoint for "add subject" and "swap teacher".** `simpanRuang` is an
  `insert … on conflict (tahun_ajaran_id, kelas_id, mapel_id) do update set
  guru_id`, backed by `ruang_scope_unique`. That is the `firstOrNew` from the
  original app. A new room takes `kkm` from `pengaturan`; an existing room keeps
  its own.
- **Every mutation returns the whole board** (`boardFor(kelasId)`), and the
  client replaces state with it. No local patching, so the screen cannot drift.
- **Clash check spans the class, not the room** (`r.kelas_id = $1 and
  r.tahun_ajaran_id = $2`), and the message names the colliding subject:
  "Bentrok dengan Prakarya dan Kewirausahaan pukul 07:30–09:00."
- **Delete guard is wider than the original.** The brief notes the reference app
  only checked `pertemuan` and `tugas`, letting a room with a quiz be deleted and
  cascade the students' attempts away. `ISI_RUANG` here is `pertemuan, tugas,
  kuis, diskusi`, each skipped while its table is missing (`to_regclass`), and
  the message lists only what is actually there: "Ruang ini sudah punya
  pertemuan, jadi tidak bisa dihapus."
- **`hapusJadwal` is scoped by class** (`delete … using ruang … r.kelas_id = $2`)
  so a stray id cannot remove another class's slot.
- **Class picker writes `?kelas=`** because it changes what the page *is*, not a
  filter within one dataset — the deep links from Kelas/Mapel land the same way.
  Unknown id falls back to the first class.

### Base UI Select gotchas hit again

- `SelectValue` renders `items[value]`. If the controlled `value` is a sentinel
  that is **not** a key in `items`, the raw string appears in the trigger — the
  Mapel dropdown literally showed "none". Fix: `value={mapelId === NONE ? null :
  mapelId}`, and the placeholder renders.
- `+ jadwal` had accessible name "jadwal", which collided with
  "Hapus jadwal Senin 07:30" under substring matching. It now carries
  `aria-label="Tambah jadwal {nama}"` — better for screen readers, unambiguous
  for tests.

## Ruang Belajar (/guru/ruang) — built, verified, closed out

The room page from the brief, end to end. Schema `scripts/migrate-ruang-belajar.ts`
(`pertemuan`, `presensi`, `materi_selesai`, `tugas`, `pengumpulan`, `kuis`, `soal`,
`percobaan`, `diskusi`; every child cascades from `ruang`). Pure helpers in
`lib/ruang-belajar-shared.ts`, data layer in `lib/ruang-belajar.ts`, server actions
in `app/actions/ruang-belajar.ts`, UI in `components/ruang-belajar/*`, three route
groups `/guru/ruang`, `/admin/ruang/[id]`, `/siswa/ruang`.

### Decisions

- **`aksesRuang(ruangId, user)` returns `{ruang, peran}`** — admin, or the assigned
  teacher (`guru_id`), or a student of that class. `notFound()` otherwise. Every
  action re-runs it, so a student POSTing a create is refused server-side.
- **`tabsFor(peran)` strips `pengaturan` for students**, and a hand-typed
  `?tab=pengaturan` falls back to `materi` instead of erroring.
- **One query per active tab**, not all seven, so opening Materi does not pay for
  the attendance matrix.
- **`badgePresensi` is the single source of truth** for the attendance badge on
  both roles. Student: own status → open window ("Presensi dibuka s.d. 15.00",
  dot not colon) → "Tidak presensi". Teacher: tally, and — added this session —
  the open window with nothing recorded also shows the closing time, because that
  is the moment the brief warns a whole class can drift to Alpa.
- **`nilaiAkhir` returns null while any component is empty**, so an ungraded class
  shows "—" rather than a misleading 33.3%.
- **Client-bundle boundary**: `*-shared.ts` holds pure types/helpers; the module
  that opens the `pg` pool is never imported by a Client Component.
- `simpanPengaturan` refuses unless the three weights sum to 100.

### Nav fix

`GURU_NAV` is now Dashboard + Ruang Belajar only. The old entries pointed at
`/admin/*`, which bounce a teacher back to `/guru` — four dead links removed.
`guru-sidebar` `isActive` also matches child routes so `/guru/ruang/73` keeps the
parent lit.

## Presensi manual per pertemuan — built and used by the teacher

Clicking a meeting card in Materi now opens an attendance sheet:
`/guru/ruang/[id]/pertemuan/[pertemuanId]`, with an admin twin at
`/admin/ruang/[id]/pertemuan/[pertemuanId]`. Both render `LembarPresensi`
(`components/ruang-belajar/lembar-presensi.tsx`, server) which mounts
`PresensiGrid` (`presensi-grid.tsx`, client).

### Decisions

- **The card is the link, not the whole `<article>`.** Wrapping the card in `<a>`
  would nest anchors, because the card already holds video/lampiran links. Instead
  the `<h3>` title is a `<Link>` with `after:absolute after:inset-0`, so a click
  anywhere hits it, and the inner anchors get `relative` so they stay above the
  overlay. Students get no link at all — a card that looks the same but behaves
  differently is worse than no affordance.
- **Nothing is written until Simpan.** The whole class is edited in local state;
  Batal restores what the DB held on load. `berubah` is a diff, so only changed
  rows are sent.
- **`status: null` means "clear the row"** and deletes it — an empty cell and a
  missing row are the same thing to every other query in the app.
- **`simpanPresensi` joins `"user"` on `kelas_id`**, so a forged `siswaId` from
  another class is silently dropped instead of written. The delete path is scoped
  by `pertemuan_id` + `any($2::text[])`.
- **Both readers are scoped by room**: `getPertemuanDetail(ruangId, pertemuanId)`
  puts `ruang_id` in the where clause, so an id from another room returns null and
  the page 404s without leaking that the meeting exists.
- **"Tandai semua hadir" overwrites every row**, not just the empty ones. It is
  explicit, and Batal makes it free to undo before saving.

### Verification

`D:\tmp\pw\presensi.mjs`, 39 checks, ALL PASS, zero console errors. It creates its
own meeting (`Uji presensi manual`, window open) so room 73's real attendance is

### Notes for next time

- **First hit on a brand-new route can throw a spurious `Could not validate
  instant` console error** (cacheComponents dev validation racing Turbopack's
  compile). It disappears on a warm run — do not chase it.
- The teacher filled PERT. 2 and PERT. 3 (42 rows each) through this page while it
  was being built, so `ruang.mjs` assertions had to become data-driven: the matrix
  tally, the `kehadiran` percentages, and the `Hadir n/42` badge now all come from

- `shots-presensi.mjs` only writes when the meeting has **zero** attendance, and
  restores that zero afterwards; otherwise it skips the save screenshot. It caught
  the teacher's fresh rows and correctly refused to touch them.

## Tugas: pengumpulan siswa + penilaian guru

The gap was total — `pengumpulan` was only ever read for two aggregate counts, and
no student could submit at all. Now the loop closes:
`/siswa/ruang/[id]/tugas/[tugasId]` (submit) and
`/guru|admin/ruang/[id]/tugas/[tugasId]` (list + grade). Components:
`halaman-tugas-siswa.tsx` + `form-pengumpulan.tsx`, `lembar-tugas.tsx` +
`nilai-tugas-grid.tsx`.

### Decisions

- **Text only for now** (the user's choice). `tipe` is still honoured in the copy,
  and a `file` task shows a blue note saying file upload is not available yet and
  to paste a link inside the text — otherwise their own `file`-type task would be
  impossible to hand in.
- **`bolehKirim()` is shared by the page and the server action**, so the button
  state and the database rule cannot drift. Order of checks: not published →
  already graded → deadline passed without lateness.
- **`dikumpulkan_at` moves on re-submission**, which is what makes `Terlambat`
  honest (`dikumpulkan_at > tenggat`, computed in SQL).
- **Grading only touches rows that already exist** — `update … from unnest(…)`
  rather than an upsert, so a grade cannot invent a submission. `nilai: null`
  clears.
- **`listTugas` now takes `lihatDraf`** and filters `terbit` for students. Before
  this, students could see the teacher's draft tasks in the Tugas tab — a leak
  that only became visible once the tab started linking somewhere.
- Draft tasks 404 on the student page too, so a direct URL leaks nothing.

### Gotcha worth remembering

**Next keeps the previous page mounted but hidden (0×0) after a soft navigation.**
`main table tbody tr` then counts two tables — 42 students + the 3 rows of the tab
it came from = 45. Use `main table:visible` in Playwright. `innerText` already
ignores the hidden copy, which is why the text assertions passed while the count
did not.

## Perbaikan: guru tidak bisa menilai (laporan pengguna)

Laporan: "halaman pengumpulan tugas sudah ada tapi guru masih belum bisa
memberikan nilai". Ini cacat yang saya buat sendiri — aturan awal saya adalah
"hanya menilai siswa yang sudah mengumpulkan", dan karena belum ada satu pun
pengumpulan, ke-42 kotak nilai `disabled` tanpa penjelasan apa pun. Tugas yang
dikumpulkan di kertas jadi mustahil dinilai.

Tiga perubahan, dan yang pertama adalah definisi datanya:

1. **`dikumpulkan` berarti ada jawaban, bukan sekadar ada baris.**
   ```sql
   (p.id is not null and (p.teks is not null or p.file_url is not null)) as dikumpulkan
   ```
   Sebelumnya baris kosong (dibuat oleh penyimpanan nilai) akan salah dihitung
   sebagai "Sudah mengumpulkan".

2. **`simpanNilaiTugas` jadi upsert + menyapu baris hantu.** Menilai tanpa
   pengumpulan itu sah, jadi barisnya dibuat kalau belum ada; lalu baris yang
   tidak punya jawaban *dan* tidak punya nilai dihapus, karena tidak membawa
   informasi apa pun.

3. **Semua kotak nilai aktif** (`disabled={pending}` saja), dan status badge
   dihitung dari state lokal, bukan dari data server, supaya tidak tertinggal
   satu langkah setelah `router.refresh()`. Ada status baru `Tanpa jawaban`
   (ungu) untuk baris yang dinilai tanpa pengumpulan, plus satu paragraf
   penjelas di atas tabel saat belum ada yang mengumpulkan.
